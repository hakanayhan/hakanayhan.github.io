Megaloop Case Study

Published mobile title built around real-time survival combat, run-based upgrade choices, secure initialization, mode-driven progression, scalable inventory systems, and configurable player-facing performance controls.

Moment-to-Moment Gameplay

Real-time survival combat with readable pressure

The core gameplay is built around surviving enemy waves, collecting resources, leveling during the run, and managing space while the pressure keeps scaling.

  • Combat readability: Enemy movement, player range, XP pickups, timers, currencies, and active abilities are surfaced without hiding the playfield.
  • Run pacing: Loop count, level progress, enemy count, and resource rewards give continuous feedback during each session.

Run Upgrade Draft

Level-up choices that shape each run

During gameplay, level-up moments present randomized upgrade choices across weapons, runes, and stat modifiers so each run develops differently.

  • Choice architecture: Upgrade cards support rarity, item type, current level, stat deltas, descriptions, banish, skip, and reroll actions.
  • Replay value: Different upgrade combinations push players toward new builds instead of repeating the same combat pattern.

Chest Rewards

Run-earned cores converted into randomized item rewards

Players earn cores during a run and spend them to open chests, creating an in-session reward loop that feeds directly back into build progression.

  • Core economy: Chest openings consume run-earned cores, turning moment-to-moment collection into a clear reward decision.
  • Randomized drops: Each chest rolls a random item, giving rewards uncertainty and supporting repeated play.
  • Rarity structure: Item rarity gives the reward table progression value and makes stronger drops feel distinct.

Build Synergy

Late-run escalation with layered weapons and items

As the run progresses, the player build becomes a layered combat system where weapons, runes, items, active skills, damage numbers, enemy waves, and pickups all interact in real time.

  • Scalable combat: Higher loops support denser enemy patterns, stronger visual effects, and multiple active systems without losing the run state.
  • Nexus active skills: Each Nexus character has a unique active skill with its own power profile, cooldown, and tactical use case.
  • Inventory feedback: The lower HUD shows equipped weapons, rune levels, items, and chest rewards so build growth remains visible.

Main Hub & Retention

Mobile survival structured around repeatable sessions

The main hub connects the gameplay loop to long-term progression, daily goals, rewards, economy, and mode selection.

  • Main menu systems: The hub connects Battle, Shop, Path rewards, Nexus, daily quests, currencies, and settings into one player flow.
  • Retention structure: Daily quests and path rewards give players clear short-term goals beyond a single run.

Universe & Mode Selection

Different universes and run modes from shared systems

The mode layer lets players move between different universes and choose between Path and Loop experiences while keeping the core gameplay architecture reusable.

  • Universe variety: Each universe can define its own environment, enemy pressure, rewards, and progression context.
  • Path and Loop modes: Loop mode supports Normal and Hard options, giving the same content structure multiple difficulty profiles.

Meta Upgrade Systems

Weapons, runes, items, and Nexus variety

The meta layer gives players multiple growth paths through weapons, runes, items, and Nexus choices, supporting different builds across repeated runs.

  • Run variety: Upgrade categories are designed to make each run feel different instead of repeating one fixed power path.
  • Data-driven scaling: Upgrade values resolve through structured definitions that can be tuned without rewriting gameplay logic.

Evolve Tree

Attack, defense, and utility progression paths

The evolve system organizes permanent progression into a node-based tree where players can invest in attack, defense, and utility upgrades.

  • Build direction: Attack, defense, and utility branches support different player priorities and play styles.
  • Tree validation: Node data enforces prerequisite chains and prevents invalid unlock order.

Shop & Monetization

IAP and ad systems integrated into the economy

The shop supports a live mobile economy with in-app purchases and ad-based reward flows built into the same entitlement and reward structure.

  • IAP implementation: Purchase flows are connected to player rewards and persistent account state.
  • Ad monetization: Rewarded ad systems are integrated and operating alongside the shop economy.

Secure Initialization

Firebase-backed login, integrity, and save resolution

The loading pipeline prepares the game by connecting Firebase services, validating the device environment, and resolving the safest player state before the session starts.

  • Integrity checks: Firebase connection, App Check, and root detection help block unsafe or unauthorized runtime conditions.
  • Session protection: The system handles same-account logins from different devices and validates the active cloud user state.
  • Save resolution: Local and cloud records are compared so the newer valid player data becomes the active session state.
  • Remote tuning: Each login pulls Remote Config values for economy, balance, and LiveOps parameters without requiring a client update.

Options, Localization & Accounts

Player settings, performance controls, and account binding

The options layer combines localization, device-friendly performance settings, platform identity, and account management in one player-facing screen.

  • 10-language localization: A centralized language system supports 10 languages and keeps adding a new language mostly to data entry rather than UI rewiring.
  • Performance options: Effect mode and FPS controls help players tune the game for different hardware profiles.
  • Account systems: Game Center, Play Games, Apple Login, Google Login, and Anonymous Login support flexible account binding.
  • Platform compliance: Account deletion support was added for store policy requirements and user data control.

In Development Prototype

Equipment system planned as the next progression layer

This prototype screen shows the equipment system currently being developed for Megaloop, extending the game beyond run upgrades into deeper long-term build customization.

  • Equipment slots: The design introduces distinct gear slots around the Nexus, alongside main weapon and active skill selections.
  • Inventory foundation: A scrollable equipment inventory is being prepared for item collection, comparison, and loadout management.

Firebase Analytics

Live visibility into players, versions, retention, and engagement

Firebase Analytics is connected to Megaloop to track release health, active users, engagement, retention, app versions, and country-level activity after launch. Between April 1 and May 19, the game reached 589 active users with 2h 17m average engagement time per active user.

  • Release monitoring: App version charts help compare player activity across live builds and verify rollout behavior.
  • Engagement signals: 589 active users and 2h 17m average engagement time show measurable session depth in the observed launch window.
  • Retention tracking: D1 retention is 32.4% and D7 retention is 9.3%, giving a concrete baseline for focused improvements to onboarding, rewards, progression pacing, and LiveOps loops.
  • Operational dashboard: Analytics turns the published game into a measurable product rather than a black-box release.
